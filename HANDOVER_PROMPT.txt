8) 当前已确认的目标函数（以当前代码优先）：
- 设 `y_ij in {0,1}` 为像素标签，`0` 表示未变化，`1` 表示变化。
- 当前代码中，双时相特征直接归一化：
`f_A(i,j) = normalize(F_A(i,j))`
`f_B(i,j) = normalize(F_B(i,j))`
- 设 `d_ij = ||f_A(i,j) - f_B(i,j)||_2` 为双时相特征距离。
- 对比损失：
`L_ctr(i,j) = (1 - y_ij) * 0.5 * d_ij^2 + y_ij * 0.5 * max(0, m - d_ij)^2`
- 图像级对比损失：
`L_ctr = clamp(mean(L_ctr(i,j)) / max(1, 0.5*m^2), 0, 1)`
- 分割分支：
`L_ce_norm = 1 - exp(-L_ce)`
`L_iou_norm = clamp(L_iou, 0, 1)`
`L_seg = alpha * L_ce_norm + (1 - alpha) * L_iou_norm`
- 总目标函数：
`L_all = (1 - beta - gamma) * L_seg + beta * L_ctr + gamma * L_edge_norm`
`L = clamp(L_all, 0, 1)`
- 代码约束：
`0 <= beta <= 1`, `0 <= gamma <= 1`, `beta + gamma <= 1`

  3) Edge_Guidance + SegFormer decode 结构。
- 可直接提供 Mermaid 代码，便于用户快速复制生成图。

20) 2026-05-22 Attention 判定结论（新增）：
- `model/sfearnet/backbone.py` 中 `Attention` 不是最朴素的全局 MHA。
- 其关键差异是 `sr_ratio` 触发的 K/V 空间降采样分支：Q 保持全分辨率 token，K/V 由卷积降采样后参与注意力计算。
- 因此在论文/答辩表述中建议称为“MiT/SegFormer-style spatial-reduction self-attention”。

21) 2026-05-22 Transformer Block 归一化说明（新增）：
- `Block` 中 `norm1` 与 `norm2` 都来自 `norm_layer`，在 `mit_b0/mit_b1` 中被实例化为 `LayerNorm(eps=1e-6)`。
- 归一化位置是 pre-norm：`x + Attn(norm1(x))`，`x + MLP(norm2(x))`。
- 建议图示中明确写“LayerNorm (token/channel dim)”以避免与 CNN 分支 BatchNorm 混淆。

22) 2026-05-22 Pyramid_Merge 图示规范（新增）：
- 面向“直观流程图”时，`Pyramid_Merge` 必须拆成两层：
  - 主模块：Path A（concat context）+ Path B（abs-diff pyramid）+ Add merge；
  - 子模块：`Pyramid_Extraction` 的 5 分支（多膨胀率 + 全局分支）及 concat/fuse。
- 推荐图注关键词：
  - Path A: complementary context enhancement
  - Path B: change-saliency extraction
  - Output: additive residual fusion

23) 2026-05-22 AbsDiff 定义澄清（新增）：
- `AbsDiff Feature` 不是 backbone 的原生单路输出。
- 它是同尺度双时相 backbone 特征的派生量：`|F_t1^s - F_t2^s|`。
- 图示建议：把 AbsDiff 画成由两路 backbone 特征汇入的运算节点，而不是 backbone 直接输出端口。

24) 2026-05-22 C1~C4 到 Pyramid_Merge 的连接澄清（新增）：
- 输入不是把 C1~C4 先拼成一个张量再融合。
- 正确流程是“逐层配对、逐层独立融合”：
  - `py1(C1_t1, C1_t2) -> F1`
  - `py2(C2_t1, C2_t2) -> F2`
  - `py3(C3_t1, C3_t2) -> F3`
  - `py4(C4_t1, C4_t2) -> F4`
- 输出仍是 4 层金字塔列表 `[F1,F2,F3,F4]`，再送入 Edge_Guidance/Decode。

25) 2026-05-22 单个 Pyramid_Merge 内部流程（新增）：
- 输入：同尺度双时相特征 `(F_t1^s, F_t2^s)`。
- 分支A（互补上下文）：`concat -> conv(1x1 DW+PW) -> CBAM`。
- 分支B（变化显著性）：`absdiff -> Pyramid_Extraction -> +absdiff`。
- 输出：`F_out^s = A + B`（逐元素加和）。
- 画图建议：将分支B中的 `+absdiff` 明确画成 residual shortcut，避免误解为纯串联卷积块。

26) 2026-05-22 分割损失计算位置澄清（新增）：
- 变化分割损失不是对 `eg[1:]` 四层特征逐层分别计算。
- 实际流程：`eg[1:]` 先送入 `decode_head` 融合为单个变化 logits，再经 `re` 上采样，最后用该 logits 计算 CE/IoU。
- 图示建议：在 decode 后画一个“Change Logits”节点，分割损失只从该节点连出。

27) 2026-05-24 解码器画图粒度建议（新增）：
- 顶层建议只画 4 个主块：
  1. 四路输入特征 `F1~F4`
  2. `Linear Embedding`
  3. `Alignment`（C2/C3/C4 对齐到 C1）
  4. `Concat -> 1x1 Fuse -> Dropout -> Classifier`

- 图里不要把它画成 U-Net 式逐级上采样；它更像“多尺度对齐后一次性融合分类头”。

35) 2026-05-24 具体尺寸约定（新增）：

36) 2026-05-24 SFEARNet 逐步数据流（新增）：
- 输入图像：`[B, 3, 256, 256]`。
- `backbone` 输出四级特征：`[B, 32, 64, 64]`, `[B, 64, 32, 32]`, `[B, 160, 16, 16]`, `[B, 256, 8, 8]`（`phi='b0'`）。
- `Pyramid_Merge` 分别融合双时相对应层特征。
- `Edge_Guidance_0/1` 输出边缘分支与增强特征。
- `decode_head` 输出变化 logits，随后经 `re/re2` 得到最终 `x/edge`。
- `feat1/feat2` 取自最深层特征并上采样到标签分辨率，用于对比损失。

37) 2026-05-24 `feat1/feat2` 与 `x1/x2` 的关系（新增）：
- `x1/x2` 是 backbone 对双时相输入返回的四级特征列表。
- `feat1 = upsample(x1[3])`，`feat2 = upsample(x2[3])`。
- 因此，`feat1/feat2` 只对应最深层特征（索引 3），并被上采样到输入分辨率。

38) 2026-05-24 使用第4层特征做对比损失的判断（新增）：
- 当前做法是合理的：对比损失只用 `x1[3]` / `x2[3]`（最深层特征）。
- 原因：深层特征更偏语义，对标签引导的相似/不相似约束更匹配。
- 注意：四个 backbone stage 分辨率不同，不能直接把整个 `x1/x2` 列表合并成一个对比输入；若要多尺度对比，需要另行设计每层单独分支。

39) 2026-05-24 伪变化场景下的对比输入选择（新增）：
- 当前建议继续使用第 4 层特征作为对比损失输入，而不是直接使用完整的 `x1/x2` 列表。
- 伪变化问题更依赖语义级判别，深层特征通常比浅层纹理特征更稳健。
- 若后续要扩展为多尺度对比，必须为每个尺度单独建分支，不能直接把不同分辨率特征混在一起。

40) 2026-05-24 多尺度对比的结论（新增）：
- 多尺度对比在理论上可能更强，但并不必然优于当前单层深层对比。
- 当前场景下，深层主分支更稳，适合先作为默认方案。
- 多尺度对比更适合作为后续消融实验候选，而不是直接替换现有实现。
